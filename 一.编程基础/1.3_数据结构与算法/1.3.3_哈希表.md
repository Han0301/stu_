# 1.3.3 哈希表 ⭐⭐

> **机器人视觉定位**：哈希表是"按 ID 快速查找"的终极武器。在多目标跟踪中，每个目标有唯一 track_id，用 `unordered_map` 可以在 O(1) 时间内找到任意目标——比遍历数组快一个数量级。

---

## 1. 本质：用"地址"换"速度"

哈希表的核心思想：**把要找的值（key）通过一个函数（hash）直接映射到它在数组中的位置**。

```
数组查找：遍历所有元素  → O(n)
哈希查找：key → hash(key) → 数组下标  → O(1)
```

```cpp
#include <unordered_map>
#include <string>

// 跟踪目标池——key 是 track_id，value 是目标信息
std::unordered_map<int, Detection> tracks;

// 插入/更新 — O(1)
tracks[1] = {100, 200, 300, 400, 0.95};
tracks[2] = {150, 250, 350, 450, 0.87};

// 查找 — O(1)
int target_id = 1;
auto it = tracks.find(target_id);
if (it != tracks.end()) {
    // 找到了！it->first = key, it->second = value
    auto& det = it->second;
} else {
    // 没找到，目标可能丢失了
}

// 删除 — O(1)
tracks.erase(target_id);
```

## 2. 哈希冲突

两个不同的 key 经过哈希函数得到了相同的下标——这就是**哈希冲突**。

### 2.1 链地址法（C++ unordered_map 的方案）

每个数组位置不存一个元素，而存一个**链表**。冲突的元素链在同一个位置后面。

```cpp
// unordered_map 的简化理解：
// 底层是 vector<list<pair<Key, Value>>>
// 查找时：hash(key) → 找到链表头 → 遍历链表找到目标 key
```

### 2.2 负载因子与重哈希

```
负载因子 = 已存元素 / 总桶数
默认负载因子 ≈ 1.0
超过负载因子 → 自动扩容（重哈希），所有元素重新计算位置 → O(n) 开销
```

```cpp
// 如果知道要存大量数据，提前预留空间，避免多次重哈希
std::unordered_map<int, Detection> tracks;
tracks.reserve(1000);  // 提前分配 1000 个桶
```

## 3. 视觉应用：多目标跟踪中的 ID 管理

```cpp
#include <unordered_map>
#include <vector>

struct TrackInfo {
    int track_id;
    float x, y, w, h;       // 当前帧的边界框
    float velocity_x, velocity_y;  // 运动速度（卡尔曼滤波用）
    int lost_count;          // 连续丢失帧数
    std::vector<float> feature;  // ReID 特征向量
};

class TrackManager {
private:
    // 核心：用哈希表按 ID 管理所有跟踪目标
    std::unordered_map<int, TrackInfo> tracks_;
    int next_id_ = 0;
    
public:
    int add_track(const TrackInfo& info) {
        int new_id = next_id_++;
        info.track_id = new_id;
        tracks_[new_id] = info;  // O(1) 插入
        return new_id;
    }
    
    bool update_track(int id, const TrackInfo& new_info) {
        auto it = tracks_.find(id);  // O(1) 查找
        if (it == tracks_.end()) return false;
        it->second = new_info;
        return true;
    }
    
    void remove_lost_tracks(int max_lost) {
        // 遍历所有目标，删除丢失过久的
        for (auto it = tracks_.begin(); it != tracks_.end(); ) {
            if (it->second.lost_count > max_lost) {
                it = tracks_.erase(it);  // O(1) 删除
            } else {
                ++it;
            }
        }
    }
    
    TrackInfo* find_track(int id) {
        auto it = tracks_.find(id);
        return it != tracks_.end() ? &it->second : nullptr;
    }
};
```

## 4. unordered_map vs map —— 怎么选？

```cpp
#include <map>   // 红黑树，O(log n)
#include <unordered_map>  // 哈希表，O(1)

// 场景 1：只需按键查找——用 unordered_map
std::unordered_map<int, Detection> by_id;  // ✅

// 场景 2：需要按键排序遍历——用 map
std::map<double, std::string> by_timestamp;  // ✅ 按时间排序

// 场景 3：数据量很小（< 100）——两者差别不大
```

| 对比 | unordered_map | map |
|------|:------------:|:---:|
| 查找 | O(1) 平均 | O(log n) |
| 有序 | ❌ 无序 | ✅ 有序（红黑树） |
| 内存 | 较大（哈希表） | 较小（红黑树节点） |
| 适用 | 按 ID 快速查找 | 需要有序遍历 |

## 面试常考

> **Q1: 哈希冲突怎么解决？**

```
C++ unordered_map 用链地址法：同一哈希桶的元素串成链表。
Java HashMap 在链表长度 > 8 时转成红黑树（优化极端情况）。
还有一种叫"开放寻址法"：冲突了就往后找空位（Python dict 用的是这个）。
```

> **Q2: 为什么哈希表查找是 O(1) 而不是真的 O(1)？**

```
理想的哈希函数能把 key 均匀映射到所有桶，那么每次查找只需一步。
但哈希冲突会导致查找退化为 O(k)，k 是冲突链长度。
所以严格来说是"均摊 O(1)"，前提是哈希函数好、负载因子适中。
```
