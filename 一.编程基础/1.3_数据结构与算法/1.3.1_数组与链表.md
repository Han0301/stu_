# 1.3.1 数组与链表 ⭐⭐

> **机器人视觉定位**：数组（`std::vector`）是视觉算法中最常用的容器——存检测框、特征点、图像数据。链表用于管理跟踪目标的 Tracklet 生命周期——频繁插入/删除时比数组快得多。

---

## 1. 数组的本质

**数组 = 连续内存上的一串相同类型的数据。** 每个元素紧挨着下一个，地址连续。

```
内存布局：[元素0][元素1][元素2][元素3]...
           ↑起始地址 + 0  +1  +2  +3
```

**数组的优势**：随机访问 O(1) —— 知道下标直接算地址，不用遍历。
**数组的劣势**：插入/删除中间元素 O(n) —— 需要移动后面所有元素。

### 1.1 C++ std::vector

```cpp
#include <vector>
#include <algorithm>

// vector 是动态数组——自动扩容
std::vector<float> scores;

// 添加元素
scores.push_back(0.95f);   // 追加到末尾，均摊 O(1)
scores.push_back(0.87f);
scores.push_back(0.92f);

// 随机访问 — O(1)
float best = scores[0];     // 直接通过下标访问

// 遍历
for (size_t i = 0; i < scores.size(); i++) {
    std::cout << scores[i] << std::endl;
}

// 范围 for 循环（推荐）
for (float s : scores) {
    std::cout << s << std::endl;
}

// 排序 — O(n log n)
std::sort(scores.begin(), scores.end(), std::greater<float>());

// 删除中间元素 — O(n)
scores.erase(scores.begin() + 1);  // 删除第 2 个元素
```

**push_back 的扩容机制：**

```
vector 内部有个容量（capacity）。
当 size == capacity 时，push_back 触发扩容：
  1. 申请一块新内存（通常为原来的 2 倍）
  2. 把旧元素全部搬过去
  3. 释放旧内存
  
所以 push_back 均摊 O(1)——大部分时间很快，偶尔慢一次。
如果提前知道数据量，用 reserve 预分配可以避免多次扩容：
  scores.reserve(1000);  // 提前分配 1000 个 float 的空间
```

## 2. 链表的本质

**链表 = 不连续内存上的一串节点，每个节点存着数据和下一个节点的地址。**

```
数组（连续）：[A] [B] [C] [D]
链表（分散）：[A]·→ [B]·→ [C]·→ [D]·→ null
```

**链表的优势**：已知位置的插入/删除 O(1) —— 只需修改相邻节点的指针。
**链表的劣势**：随机访问 O(n) —— 必须从头一个个往后找。

### 2.1 C++ 双向链表实现

```cpp
#include <iostream>

// 双向链表节点
struct TrackNode {
    int track_id;           // 跟踪目标 ID
    float x, y, w, h;      // 当前边界框
    int lost_count;         // 连续丢失帧数
    
    TrackNode* prev;        // 指向前一个节点
    TrackNode* next;        // 指向后一个节点
    
    // 构造函数
    TrackNode(int id, float bx, float by, float bw, float bh)
        : track_id(id), x(bx), y(by), w(bw), h(bh)
        , lost_count(0), prev(nullptr), next(nullptr) {}
};

class TrackletList {
private:
    TrackNode* head_;  // 链表头
    TrackNode* tail_;  // 链表尾
    int size_;
    
public:
    TrackletList() : head_(nullptr), tail_(nullptr), size_(0) {}
    
    ~TrackletList() {
        // 释放所有节点
        TrackNode* cur = head_;
        while (cur) {
            TrackNode* next = cur->next;
            delete cur;
            cur = next;
        }
    }
    
    // 在链表尾部添加新跟踪目标 — O(1)
    void add_track(int id, float x, float y, float w, float h) {
        auto* node = new TrackNode(id, x, y, w, h);
        if (tail_ == nullptr) {
            head_ = tail_ = node;
        } else {
            tail_->next = node;
            node->prev = tail_;
            tail_ = node;
        }
        size_++;
    }
    
    // 删除指定节点 — 已知位置 O(1)
    void remove_track(TrackNode* node) {
        if (node->prev)
            node->prev->next = node->next;
        if (node->next)
            node->next->prev = node->prev;
        if (node == head_) head_ = node->next;
        if (node == tail_) tail_ = node->prev;
        delete node;
        size_--;
    }
    
    // 清理丢失超过 max_lost 帧的目标
    void clean_lost(int max_lost) {
        TrackNode* cur = head_;
        while (cur) {
            TrackNode* next = cur->next;
            if (cur->lost_count > max_lost) {
                remove_track(cur);
            }
            cur = next;
        }
    }
    
    // 遍历所有目标
    void for_each(void (*callback)(const TrackNode*)) {
        TrackNode* cur = head_;
        while (cur) {
            callback(cur);
            cur = cur->next;
        }
    }
    
    int size() const { return size_; }
    TrackNode* head() const { return head_; }
};
```

## 3. 数组 vs 链表——怎么选？

| 操作 | 数组（vector） | 链表（list） |
|------|:-------------:|:-----------:|
| 随机访问（arr[5]） | O(1) ✅ | O(n) ❌ |
| 末尾插入/删除 | O(1) ✅ | O(1) ✅ |
| 中间插入/删除 | O(n) ❌ | O(1) ✅（已知位置） |
| 内存占用 | 小（只存数据） | 大（额外存 prev/next） |
| CPU 缓存友好 | ✅ 连续内存 | ❌ 分散内存 |

**视觉中的选择原则：**
```
- 存检测结果 → vector（需要随机访问和排序，不需要中间插入）
- 存跟踪目标 → list（需要频繁插入/删除，不需要随机访问）
- 存图像数据 → vector<uchar>（连续内存，CPU 缓存友好）
```

## 面试常考

> **Q1: 为什么 vector 的 push_back 是"均摊 O(1)"？**

```
每次扩容时确实 O(n)，但扩容后容量翻倍。
所以总共 n 次 push_back 中，只有 log n 次需要搬移。
总操作数 ≈ n + n/2 + n/4 + ... = 2n，所以均摊 O(1)。
```

> **Q2: 什么场景下数组比链表快？即使链表理论复杂度更优？**

```
数组的内存是连续的，CPU 加载一个元素时会顺便把相邻元素也加载到缓存。
链表的节点分散在各处，每次访问都可能缓存不命中。
实际测试中，即使中间插入，数组有时也比链表快——因为内存访问模式更好。
```

## 2. 栈与队列 ⭐⭐

### 2.1 栈（Stack）——LIFO

```python
# Python 的 list 即可作为栈
stack = []
stack.append("frame1")   # push
stack.append("frame2")
last = stack.pop()       # pop → "frame2"
```

**视觉用途**：DFS 遍历图像连通域、撤销操作（图像编辑）。

### 2.2 队列（Queue）——FIFO

```python
from collections import deque

# BFS 遍历图像——连通域分析
def bfs_connected_components(binary_img):
    """用 BFS 标记连通区域"""
    h, w = binary_img.shape
    visited = np.zeros_like(binary_img, dtype=bool)
    q = deque()
    components = []
    
    for y in range(h):
        for x in range(w):
            if binary_img[y, x] and not visited[y, x]:
                # 发现新连通域
                component = []
                q.append((x, y))
                visited[y, x] = True
                
                while q:
                    cx, cy = q.popleft()  # FIFO
                    component.append((cx, cy))
                    
                    # 四邻域搜索
                    for dx, dy in [(1,0), (-1,0), (0,1), (0,-1)]:
                        nx, ny = cx+dx, cy+dy
                        if 0 <= nx < w and 0 <= ny < h:
                            if binary_img[ny, nx] and not visited[ny, nx]:
                                visited[ny, nx] = True
                                q.append((nx, ny))
                
                components.append(component)
    
    return components
```

### 2.3 优先队列（Priority Queue / Heap）——NMS

```python
import heapq

def nms_with_heap(detections, iou_threshold=0.5):
    """
    用最大堆实现 NMS
    detections: [(x1, y1, x2, y2, score), ...]
    时间复杂度 O(n log n)
    """
    # Python heapq 是最小堆，存负值模拟最大堆
    heap = [(-score, x1, y1, x2, y2) 
            for x1, y1, x2, y2, score in detections]
    heapq.heapify(heap)
    
    keep = []
    while heap:
        # 取置信度最高的框
        neg_score, *box = heapq.heappop(heap)
        keep.append(box)
        
        # 重新建堆——移出与当前框 IoU 过高的
        # （实际 NMS 有更高效的实现，这里展示堆的思想）
        remaining = []
        for item in heap:
            _, *other = item
            if compute_iou(box, other) < iou_threshold:
                remaining.append(item)
        heap = remaining
        heapq.heapify(heap)
    
    return keep
```

### 2.4 双端队列（Deque）——滑动窗口

```python
from collections import deque

# 滑动窗口均值滤波
def sliding_window_average(data, window_size=5):
    """对时序数据做滑动窗口平均"""
    window = deque(maxlen=window_size)
    result = []
    
    for value in data:
        window.append(value)
        result.append(sum(window) / len(window))
    
    return result

# 应用：平滑检测框的抖动
raw_boxes = [(100, 200), (102, 198), (101, 201), (103, 199)]
smoothed = sliding_window_average(raw_boxes)
```

## 3. 哈希表 ⭐⭐

### 3.1 Python 字典——按 ID 快速查找

```python
# 跟踪目标池——O(1) 查找/插入/删除
tracked = {}

tracked[1] = {"bbox": (100, 200, 300, 400), "score": 0.95}
tracked[2] = {"bbox": (150, 250, 350, 450), "score": 0.87}

# 快速查找
if target_id in tracked:  # O(1)
    obj = tracked[target_id]

# 删除
del tracked[target_id]
```

### 3.2 C++ unordered_map

```cpp
#include <unordered_map>

// 按 track_id 管理目标
std::unordered_map<int, Detection> tracks;

// 插入
tracks[1] = {100, 200, 300, 400, 0.95};

// 查找
auto it = tracks.find(target_id);
if (it != tracks.end()) {
    // 找到
}

// 遍历
for (const auto& [id, det] : tracks) {
    std::cout << "Track " << id << ": score=" << det.score;
```

## 面试常考

> **Q1: 数组和链表的区别？**

```
数组：连续内存，随机访问 O(1)，插入删除 O(n)
链表：分散内存，随机访问 O(n)，已知位置插入删除 O(1)
视觉中：存检测框用 vector（连续内存，cache 友好），管理 Tracklet 用链表
```

> **Q2: 什么场景用栈，什么场景用队列？**

```
栈（LIFO）：DFS、函数调用栈、撤销操作
队列（FIFO）：BFS、视频帧缓冲、消息队列
优先队列（堆）：NMS 候选框排序、Top-K 检测
```
