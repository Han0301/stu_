# 1.3.1 数组与链表 ⭐⭐

> **机器人视觉定位**：数组（`std::vector`）是视觉算法中最常用的容器——存检测框、特征点、图像数据。链表用于管理跟踪目标的 Tracklet 生命周期——频繁插入/删除时比数组快得多。

---

## 1. 数组的本质

**数组 = 连续内存上的一串相同类型的数据。** 每个元素紧挨着下一个，地址连续。

```
内存布局：[元素0][元素1][元素2][元素3]...
           ↑起始地址 + 0  +1  +2  +3
```

**数组的优势**：随机访问 O(1) —— 知道下标直接算地址，不用遍历。
**数组的劣势**：插入/删除中间元素 O(n) —— 需要移动后面所有元素。

### 1.1 C++ std::vector

```cpp
#include <vector>
#include <algorithm>

// vector 是动态数组——自动扩容
std::vector<float> scores;

// 添加元素
scores.push_back(0.95f);   // 追加到末尾，均摊 O(1)
scores.push_back(0.87f);
scores.push_back(0.92f);

// 随机访问 — O(1)
float best = scores[0];     // 直接通过下标访问

// 遍历
for (size_t i = 0; i < scores.size(); i++) {
    std::cout << scores[i] << std::endl;
}

// 范围 for 循环（推荐）
for (float s : scores) {
    std::cout << s << std::endl;
}

// 排序 — O(n log n)
std::sort(scores.begin(), scores.end(), std::greater<float>());

// 删除中间元素 — O(n)
scores.erase(scores.begin() + 1);  // 删除第 2 个元素
```

**push_back 的扩容机制：**

```
vector 内部有个容量（capacity）。
当 size == capacity 时，push_back 触发扩容：
  1. 申请一块新内存（通常为原来的 2 倍）
  2. 把旧元素全部搬过去
  3. 释放旧内存
  
所以 push_back 均摊 O(1)——大部分时间很快，偶尔慢一次。
如果提前知道数据量，用 reserve 预分配可以避免多次扩容：
  scores.reserve(1000);  // 提前分配 1000 个 float 的空间
```

## 2. 链表的本质

**链表 = 不连续内存上的一串节点，每个节点存着数据和下一个节点的地址。**

```
数组（连续）：[A] [B] [C] [D]
链表（分散）：[A]·→ [B]·→ [C]·→ [D]·→ null
```

**链表的优势**：已知位置的插入/删除 O(1) —— 只需修改相邻节点的指针。
**链表的劣势**：随机访问 O(n) —— 必须从头一个个往后找。

### 2.1 C++ 双向链表实现

```cpp
#include <iostream>

// 双向链表节点
struct TrackNode {
    int track_id;           // 跟踪目标 ID
    float x, y, w, h;      // 当前边界框
    int lost_count;         // 连续丢失帧数
    
    TrackNode* prev;        // 指向前一个节点
    TrackNode* next;        // 指向后一个节点
    
    // 构造函数
    TrackNode(int id, float bx, float by, float bw, float bh)
        : track_id(id), x(bx), y(by), w(bw), h(bh)
        , lost_count(0), prev(nullptr), next(nullptr) {}
};

class TrackletList {
private:
    TrackNode* head_;  // 链表头
    TrackNode* tail_;  // 链表尾
    int size_;
    
public:
    TrackletList() : head_(nullptr), tail_(nullptr), size_(0) {}
    
    ~TrackletList() {
        // 释放所有节点
        TrackNode* cur = head_;
        while (cur) {
            TrackNode* next = cur->next;
            delete cur;
            cur = next;
        }
    }
    
    // 在链表尾部添加新跟踪目标 — O(1)
    void add_track(int id, float x, float y, float w, float h) {
        auto* node = new TrackNode(id, x, y, w, h);
        if (tail_ == nullptr) {
            head_ = tail_ = node;
        } else {
            tail_->next = node;
            node->prev = tail_;
            tail_ = node;
        }
        size_++;
    }
    
    // 删除指定节点 — 已知位置 O(1)
    void remove_track(TrackNode* node) {
        if (node->prev)
            node->prev->next = node->next;
        if (node->next)
            node->next->prev = node->prev;
        if (node == head_) head_ = node->next;
        if (node == tail_) tail_ = node->prev;
        delete node;
        size_--;
    }
    
    // 清理丢失超过 max_lost 帧的目标
    void clean_lost(int max_lost) {
        TrackNode* cur = head_;
        while (cur) {
            TrackNode* next = cur->next;
            if (cur->lost_count > max_lost) {
                remove_track(cur);
            }
            cur = next;
        }
    }
    
    // 遍历所有目标
    void for_each(void (*callback)(const TrackNode*)) {
        TrackNode* cur = head_;
        while (cur) {
            callback(cur);
            cur = cur->next;
        }
    }
    
    int size() const { return size_; }
    TrackNode* head() const { return head_; }
};
```

## 3. 数组 vs 链表——怎么选？

| 操作 | 数组（vector） | 链表（list） |
|------|:-------------:|:-----------:|
| 随机访问（arr[5]） | O(1) ✅ | O(n) ❌ |
| 末尾插入/删除 | O(1) ✅ | O(1) ✅ |
| 中间插入/删除 | O(n) ❌ | O(1) ✅（已知位置） |
| 内存占用 | 小（只存数据） | 大（额外存 prev/next） |
| CPU 缓存友好 | ✅ 连续内存 | ❌ 分散内存 |

**视觉中的选择原则：**
```
- 存检测结果 → vector（需要随机访问和排序，不需要中间插入）
- 存跟踪目标 → list（需要频繁插入/删除，不需要随机访问）
- 存图像数据 → vector<uchar>（连续内存，CPU 缓存友好）
```

## 面试常考

> **Q1: 为什么 vector 的 push_back 是"均摊 O(1)"？**

```
每次扩容时确实 O(n)，但扩容后容量翻倍。
所以总共 n 次 push_back 中，只有 log n 次需要搬移。
总操作数 ≈ n + n/2 + n/4 + ... = 2n，所以均摊 O(1)。
```

> **Q2: 什么场景下数组比链表快？即使链表理论复杂度更优？**

```
数组的内存是连续的，CPU 加载一个元素时会顺便把相邻元素也加载到缓存。
链表的节点分散在各处，每次访问都可能缓存不命中。
实际测试中，即使中间插入，数组有时也比链表快——因为内存访问模式更好。
```

在目标跟踪中，为什么用链表管理 Tracklet 比用 vector 更合适？请从插入/删除频率和随机访问需求两个角度分析。

**5. 原理追问** ⭐⭐
为什么说 vector 的 push_back 是"均摊 O(1)"？什么情况下它的时间复杂度会退化为 O(n)？

**参考答案**
1. 数组连续内存（随机访问快，插入删除慢）；链表离散内存（随机访问慢，插入删除快）
2. 略
3. `reserve` 预分配容量但 size 不变；`resize` 改变 size 并默认构造元素
4. 跟踪中频繁新建和删除目标（出现/消失），用链表 O(1)；用 vector 删除中间元素 O(n)
5. 均摊 O(1) 因为扩容翻倍；最坏情况 push_back 正好触发出现在扩容那一刻，单次 O(n)
