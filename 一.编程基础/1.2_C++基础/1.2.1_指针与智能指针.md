# 1.2.1 指针、引用与智能指针

> **机器人视觉定位**：指针和引用是 C++ 区别于 Python 的核心特征。在 TensorRT 推理引擎管理中，`unique_ptr` 确保显存自动释放；在 ROS 消息传递中，引用避免大体积图像数据的拷贝。**智能指针 + RAII** 是写健壮 C++ 代码的基石。

---

## 1. 指针 vs 引用

| 特性 | 指针 | 引用 |
|------|------|------|
| 语法 | `int* p = &a` | `int& r = a` |
| 可重新绑定 | ✅ 可指向其他变量 | ❌ 初始化后不可变 |
| 空值 | ✅ 可为 `nullptr` | ❌ 必须初始化 |
| 解引用 | 需要 `*p` | 自动解引用 |
| 视觉用途 | 可选参数、动态数组 | 函数参数传递（避免拷贝） |

```cpp
#include <iostream>
#include <vector>

// ✅ 引用传参——避免拷贝图像数据
void preprocess(const cv::Mat& input, cv::Mat& output) {
    // input: 只读引用，不拷贝 4K 图像数据
    // output: 输出引用，直接写入结果
    cv::resize(input, output, cv::Size(640, 384));
}

// ❌ 值传参——每次拷贝整个图像，性能灾难
void bad_preprocess(cv::Mat input) {  // 拷贝了整张图！
    // ...
}
```

### 指针与 const

```cpp
// 四种 const 组合——面试常问
const int* p;       // 指向 const int（值不可改，地址可改）
int* const p;       // const 指针（地址不可改，值可改）
const int* const p; // 全 const
int const* p;       // 同 const int*（const 在类型前后等价）
```

## 2. 智能指针 ⭐⭐⭐

### 2.1 `std::unique_ptr`——独占所有权

```cpp
#include <memory>

class TensorRTEngine {
public:
    TensorRTEngine(const std::string& path) {
        // 加载模型
    }
    void infer() { /* 推理 */ }
};

// unique_ptr：独占所有权，不能拷贝，只能移动
auto engine = std::make_unique<TensorRTEngine>("model.trt");
engine->infer();

// auto engine2 = engine;          // ❌ 禁止拷贝
auto engine2 = std::move(engine);  // ✅ 移动语义
// engine 此时为 nullptr
```

### 2.2 `std::shared_ptr`——共享所有权

```cpp
class Detector {
public:
    explicit Detector(const std::string& model_path) {
        std::cout << "加载模型: " << model_path << std::endl;
    }
    ~Detector() {
        std::cout << "释放模型资源" << std::endl;
    }
};

// shared_ptr：多个指针共享同一对象，引用计数自动管理
auto detector1 = std::make_shared<Detector>("yolov8.pt");
{
    auto detector2 = detector1;  // 引用计数 +1
    detector2->detect(frame);
}  // detector2 销毁，引用计数 -1

// detector1 还活着，模型未被释放
detector1->detect(frame);
// 当 detector1 也销毁时，引用计数归零，自动 delete
```

### 2.3 `std::weak_ptr`——打破循环引用

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;  // 用 weak_ptr 避免循环引用
    ~Node() { std::cout << "Node 销毁" << std::endl; }
};

auto n1 = std::make_shared<Node>();
auto n2 = std::make_shared<Node>();
n1->next = n2;
n2->prev = n1;  // weak_ptr，不会增加引用计数
// 析构时不会内存泄漏 ✅
```

## 3. RAII 原则 ⭐⭐⭐

**RAII（Resource Acquisition Is Initialization）**：资源获取即初始化。

| 资源类型 | 构造函数获取 | 析构函数释放 |
|----------|-------------|-------------|
| 堆内存 | `new` / `malloc` | `delete` / `free` |
| 文件句柄 | `fopen` | `fclose` |
| CUDA 显存 | `cudaMalloc` | `cudaFree` |
| TensorRT 引擎 | `createInferRuntime` | `destroy` |
| 互斥锁 | `lock` | `unlock` |

```cpp
class CUDAMemory {
    // RAII 封装 CUDA 显存管理
public:
    CUDAMemory(size_t size) {
        cudaError_t err = cudaMalloc(&ptr_, size);
        if (err != cudaSuccess) {
            throw std::runtime_error("CUDA malloc 失败");
        }
    }
    
    ~CUDAMemory() {
        if (ptr_) {
            cudaFree(ptr_);  // 自动释放显存 ✅
        }
    }
    
    // 禁止拷贝
    CUDAMemory(const CUDAMemory&) = delete;
    CUDAMemory& operator=(const CUDAMemory&) = delete;
    
    // 允许移动
    CUDAMemory(CUDAMemory&& other) noexcept : ptr_(other.ptr_) {
        other.ptr_ = nullptr;
    }

private:
    void* ptr_ = nullptr;
};

// 使用——不用担心忘记 cudaFree
{
    CUDAMemory gpu_mem(1024 * 1024 * 100);  // 申请 100MB 显存
    // 使用显存...
}  // 自动释放 ✅
```

## 4. 面试高频问题

> **Q1: `unique_ptr` 和 `shared_ptr` 的区别？**

```
unique_ptr：独占所有权，轻量（大小等于裸指针），只能 move
shared_ptr：共享所有权，带引用计数（大小约等于 2 个指针），可拷贝
推荐：默认用 unique_ptr，确实需要共享才用 shared_ptr
```

> **Q2: RAII 在视觉项目中的实际应用？**

```
TensorRT 引擎管理：构造时加载 → 析构时卸载
CUDA 显存管理：构造时 cudaMalloc → 析构时 cudaFree
ROS 节点生命周期：构造时初始化 → 析构时 shutdown
```

> **Q3: 什么时候用指针，什么时候用引用？**

```
引用：函数参数传递（避免拷贝，且语义清晰）
指针：可选参数（可为 nullptr）、动态数组、需要重新绑定
```

## 必须掌握的要点

1. **智能指针**：`unique_ptr`（默认首选）、`shared_ptr`（共享）、`weak_ptr`（打破循环）
2. **RAII 原则**：构造函数拿资源、析构函数释放——TensorRT/CUDA 编程的核心模式
3. **`const` 指针**：四种 const 组合的含义
4. **引用传参**：`const T&` 是避免拷贝的首选方式
