# 八、模型部署与优化

> **与机器人视觉感知的关联**：模型部署是将实验室算法变为**机器人上实时运行的感知系统**的关键环节。机器人视觉对推理有**严格的实时性要求**（通常要求 30FPS+），而边缘设备（Jetson、手机 SoC、FPGA）算力远小于服务器 GPU。**模型压缩、量化、引擎优化**是机器人视觉工程师的必备技能。这个模块的能力决定了你做的算法能不能"跑起来"。

---

## 8.1 ONNX（Open Neural Network Exchange）⭐⭐⭐

ONNX 是模型部署的**中间桥梁**，几乎所有训练框架（PyTorch/TensorFlow）都可以导出 ONNX，几乎所有推理引擎（TensorRT/ONNX Runtime/OpenVINO）都可以加载 ONNX。

### 8.1.1 ONNX 基础

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **ONNX 结构** | protobuf 格式、计算图（Graph）+ 节点（Node）+ 张量（Tensor）+ 初始值（Initializer） | ⭐⭐⭐ |
| **算子集（Opset）** | 算子版本控制（如 opset=11/12/17/21），高版本兼容低版本 | ⭐⭐⭐ |
| **静态轴 vs 动态轴** | 静态：所有维度固定；动态：batch/宽/高可变（用 `dynamic_axes`） | ⭐⭐⭐ |
| **IR 版本** | 中间表示版本号 | ⭐⭐ |

### 8.1.2 PyTorch → ONNX 导出 ⭐⭐⭐

```python
import torch.onnx

# 导出 ONNX 的核心参数
torch.onnx.export(
    model,                                    # PyTorch 模型
    dummy_input,                              # 示例输入 (决定输入shape)
    "model.onnx",                             # 输出路径
    export_params=True,                       # 导出训练好的参数
    opset_version=17,                         # opset 版本（越高支持的算子越新）
    do_constant_folding=True,                 # 常量折叠优化
    input_names=['input'],                    # 输入张量名
    output_names=['output'],                  # 输出张量名
    dynamic_axes={                            # 动态轴定义
        'input': {0: 'batch_size', 2: 'height', 3: 'width'},
        'output': {0: 'batch_size'}
    }
)
```

### 8.1.3 ONNX 调试与优化

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **ONNX Runtime** | `pip install onnxruntime-gpu`，Python/C++ 推理 | ⭐⭐⭐ |
| **onnxruntime 推理** | `ort.InferenceSession`、`run()`、IO Binding | ⭐⭐⭐ |
| **ONNX 可视化** | Netron (https://netron.app) 在线看图 | ⭐⭐⭐ |
| **onnx-simplifier** | 简化 ONNX 图：常量折叠、冗余消除 | ⭐⭐⭐ |
| **onnx-graphsurgeon** | NVIDIA 的 ONNX 图编辑工具（自定义算子替换） | ⭐⭐ |
| **opset 兼容问题** | 某些 PyTorch 算子（如 `torch.stack` / `torch.meshgrid`）导出需注意 | ⭐⭐⭐ |

## 8.2 TensorRT ⭐⭐⭐

NVIDIA 的推理优化引擎，是机器人视觉部署到 NVIDIA 平台的首选。

### 8.2.1 TensorRT 核心概念

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **Engine（引擎）** | `trtexec --onnx=model.onnx --saveEngine=model.trt` 序列化引擎 | ⭐⭐⭐ |
| **Builder** | 构建引擎的配置入口 | ⭐⭐ |
| **Network Definition** | TensorRT 内部的计算图表示 | ⭐⭐ |
| **Layer Fusion** | 自动合并相邻层（Conv+BN+ReLU → CBR） | ⭐⭐⭐ |
| **Kernel Auto-Tuning** | 为每个算子选择最快的内核实现（基于硬件） | ⭐⭐ |
| **精度模式** | FP32 / FP16 / INT8 / INT4 | ⭐⭐⭐ |
| **动态 shape** | `OPTProfile`：指定 min/opt/max 三种尺寸 | ⭐⭐⭐ |

### 8.2.2 TensorRT 工作流

```text
PyTorch 模型 (.pt/.pth)
    ↓ torch.onnx.export
ONNX 模型 (.onnx)
    ↓ trtexec / Python API
TensorRT Engine (.trt / .plan)
    ↓
推理 (Python/C++ Runtime)
```

#### 命令行快速转换（trtexec）

```bash
# FP32 引擎
trtexec --onnx=model.onnx --saveEngine=model_fp32.trt

# FP16 引擎（速度提升 ~2x）
trtexec --onnx=model.onnx --fp16 --saveEngine=model_fp16.trt

# INT8 引擎（速度提升 ~3-4x，需要校准数据集）
trtexec --onnx=model.onnx --int8 --calib=calibration_images \
        --saveEngine=model_int8.trt

# 动态 shape
trtexec --onnx=model.onnx --minShapes=input:1x3x320x320 \
        --optShapes=input:1x3x640x640 \
        --maxShapes=input:1x3x1280x1280 \
        --saveEngine=model_dynamic.trt
```

### 8.2.3 Python 端 TensorRT 推理 ⭐⭐⭐

```python
import tensorrt as trt
import pycuda.driver as cuda

class TRTInference:
    def __init__(self, engine_path):
        self.logger = trt.Logger(trt.Logger.INFO)
        self.runtime = trt.Runtime(self.logger)
        with open(engine_path, 'rb') as f:
            self.engine = self.runtime.deserialize_cuda_engine(f.read())
        self.context = self.engine.create_execution_context()

        # 分配 GPU 显存
        self.inputs, self.outputs, self.bindings = [], [], []
        for i in range(self.engine.num_bindings):
            name = self.engine.get_binding_name(i)
            shape = self.engine.get_binding_shape(i)
            size = trt.volume(shape)
            dtype = trt.nptype(self.engine.get_binding_dtype(i))
            alloc = cuda.mem_alloc(size * np.dtype(dtype).itemsize)
            self.bindings.append(int(alloc))

            if self.engine.binding_is_input(i):
                self.inputs.append({'name': name, 'alloc': alloc, 'shape': shape, 'dtype': dtype})
            else:
                self.outputs.append({'name': name, 'alloc': alloc, 'shape': shape, 'dtype': dtype})

    def infer(self, input_np):
        cuda.memcpy_htod(self.inputs[0]['alloc'], input_np)
        self.context.execute_v2(self.bindings)
        output = np.empty(self.outputs[0]['shape'], dtype=self.outputs[0]['dtype'])
        cuda.memcpy_dtoh(output, self.outputs[0]['alloc'])
        return output
```

### 8.2.4 TensorRT 高级技巧

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **FP16/INT8 量化** | 精度评估（mAP 下降 < 1% 可接受）、校准数据选择 | ⭐⭐⭐ |
| **INT8 校准原理** | KL 散度校准（最小化 FP32 和 INT8 的分布差异） | ⭐⭐⭐ |
| **Plugin 自定义算子** | C++ 实现 TensorRT 不支持的算子（如特殊激活函数） | ⭐⭐ |
| **多 stream 推理** | 多线程推理（cuda stream）→ 提高吞吐量 | ⭐⭐ |
| **DLA (Deep Learning Accelerator)** | Jetson 的专用深度学习加速器 | ⭐ |
| **TensorRT Profiling** | `trtexec --profiling` / Nsight Systems 分析各层耗时 | ⭐⭐⭐ |

### 8.2.5 精度评估

```text
量化后必须验证精度损失：
    1. 用 FP32 引擎推理 validation set → 记录 mAP
    2. 用 FP16/INT8 引擎推理 → 记录 mAP
    3. 对比：mAP 下降 < 1% → 量化合格
           mAP 下降 1-3% → 需要调校准数据/校准算法
           mAP 下降 > 3% → 模型对量化敏感，需 QAT
```

## 8.3 量化技术 ⭐⭐⭐

### 8.3.1 PTQ（Post-Training Quantization）vs QAT（Quantization-Aware Training）

| 对比项 | PTQ | QAT |
|--------|-----|-----|
| **流程** | 训练完 → 直接量化 | 训练中模拟量化 → 微调后导出 |
| **数据需求** | 需要校准数据（几百张） | 需要训练数据 |
| **精度损失** | 通常 < 1% | 可接近 FP32 |
| **耗时** | 几分钟 | 重新训练一轮 |
| **适用** | 大部分模型 | 对量化敏感的模型（小模型/极端轻量模型） |

### 8.3.2 量化原理

```text
FP32 → INT8 量化的基本公式：
    x_int8 = clamp(round(x_fp32 / scale) + zero_point)
    
其中:
    scale = (x_max - x_min) / 255
    zero_point 让量化后的零点对齐
    
对称量化: zero_point = 0 (TensorRT 默认)
非对称量化: zero_point ≠ 0
```

## 8.4 模型轻量化 ⭐⭐

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **通道剪枝** | 移除不重要的卷积通道（基于 BN γ 值/L1 norm） | ⭐⭐ |
| **结构化剪枝** | 剪掉整个滤波器/通道（硬件友好） | ⭐⭐ |
| **非结构化剪枝** | 剪掉单个权重（稀疏，需硬件支持） | ⭐ |
| **知识蒸馏** | Teacher（大模型）→ Student（小模型）、logits 蒸馏/特征蒸馏 | ⭐⭐ |
| **轻量网络设计** | MobileNet / ShuffleNet / GhostNet 的设计原则 | ⭐⭐ |

### 8.5.2 部署流程模板

```text
1. 训练模型（PyTorch）→ 验证达标
2. 导出 ONNX → simplifier 简化 → 验证 ONNX 推理正确
3. 转 TensorRT Engine → FP16/INT8 量化
4. 精度验证（对比 ONNX 推理结果）
5. 编写推理代码（Python/C++）
6. 集成到 ROS 节点
7. Profiling 优化（确保达到目标帧率）
8. Jetson 上测试功耗/散热
```

### 8.5.3 常见部署 Pipeline

| 场景 | 推荐方案 | 预期帧率 (Jetson Orin) |
|------|---------|----------------------|
| 检测 (YOLOv8s) | TensorRT FP16 | ~100 FPS |
| 检测 (YOLOv8n) | TensorRT INT8 | ~200 FPS |
| 分割 (UNet) | TensorRT FP16 | ~60 FPS |
| 深度估计 (MiDaS) | TensorRT FP16 | ~30 FPS |
| 3D 检测 (PointPillars) | TensorRT FP16 | ~40 FPS |
