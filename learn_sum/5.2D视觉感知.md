# 五、2D 视觉感知

> **与机器人视觉感知的关联**：2D 视觉感知是机器人感知系统的"入口层"。机器人需要从图像中回答三个基本问题：**"这是什么？"**（分类）、**"它在哪里？"**（检测）、**"它往哪去？"**（跟踪）。虽然最终目标是 3D 空间感知，但 2D 检测和跟踪是绝大多数机器人视觉系统的上游模块，其输出质量直接影响后续的 3D 重建、轨迹预测和决策规划。20K 岗位面试中，**目标检测和多目标跟踪**是最核心的两个考察点。

---

## 5.1 图像分类

图像分类是理解所有视觉模型的基础，检测/分割/跟踪等复杂任务都建立在分类器之上。

| 知识点 | 详细内容 | 与机器人视觉的关联 | 掌握程度 |
|--------|---------|------------------|---------|
| **分类框架** | Backbone + Global Pooling + FC + Softmax | 理解"特征提取 → 决策"的基础范式 | ⭐⭐⭐ |
| **ResNet 系列** | ResNet-18/34/50/101 结构差异、Bottleneck vs BasicBlock、各层通道数 | 检测模型最常用的 Backbone，必须能画出结构图 | ⭐⭐⭐ |
| **MobileNet 系列** | v1（深度可分离）、v2（倒残差+线性瓶颈）、v3（NAS+h-swish） | **边缘部署首选**，Jetson/手机端机器人必用 | ⭐⭐⭐ |
| **EfficientNet** | MBConv、SE 模块、复合缩放系数 φ | 理解"分辨率/深度/宽度"三者关系 | ⭐⭐ |
| **ViT** | Patch Embedding、位置编码、CLS Token、注意力机制 | **现代趋势**：检测/分割 SOTA 模型的基础组件 | ⭐⭐⭐ |
| **Swin Transformer** | 窗口注意力 W-MSA、窗口偏移 SW-MSA、层级特征 | 理解 如何用 Transformer 做视觉 Backbone | ⭐⭐ |
| **Fine-tune 策略** | 冻结 Backbone vs 全参数微调、分层学习率、判别式学习率 | **工程必备**：用预训练模型 + 自己的数据 | ⭐⭐⭐ |
| **多标签分类** | BCE Loss、阈值选取、不均衡类别处理 | 机器人场景中一图可能有多个物体类别 | ⭐⭐ |

### 分类模型的机器人应用场景

- **物体识别**：识别机器人物体抓取的目标类别
- **场景分类**：区分室内/室外/隧道等场景 → 切换感知策略
- **质量筛选**：过滤模糊/过曝/异常帧，只处理高质量图像

### 5.2.5 核心机制详解（面试必问）

#### 正负样本分配 ⭐⭐⭐

| 方法 | 核心思想 | 应用 |
|------|---------|------|
| **Max IoU Assigner** | Anchor 与 GT 的最大 IoU > 阈值 → 正样本 | Faster R-CNN |
| **ATSS** | 自适应训练样本选择（按 IoU 均值+标准差动态设阈值） | FCOS、部分 YOLO 改进 |
| **SimOTA** | 简化的最优传输分配（按 cost 矩阵分配） | YOLOX |
| **TaskAlignedAssigner** | 结合分类得分+回归 IoU 的对齐度 `t = s^α × IoU^β` | **YOLOv8 使用** |

#### NMS（非极大值抑制） ⭐⭐⭐

```python
# 必须能手写的 NMS
def nms(boxes, scores, iou_threshold):
    indices = np.argsort(scores)[::-1]
    keep = []
    while len(indices) > 0:
        i = indices[0]
        keep.append(i)
        # 计算剩余框与当前框的 IoU
        ious = compute_iou(boxes[i], boxes[indices[1:]])
        # 保留 IoU < 阈值的框
        indices = indices[1:][ious < iou_threshold]
    return keep
```

**NMS 变体**：
- **Soft-NMS**：Iou 高的框不直接删，而是降低分数（`s_i = s_i × (1-IoU)` 或高斯衰减）
- **NMS-free**：YOLOv10 通过一致匹配训练解耦 NMS

#### 评估指标 mAP ⭐⭐⭐

| 概念 | 含义 |
|------|------|
| **IoU** | 预测框与 GT 框的交并比 |
| **Precision/Recall** | 准确率 = TP/(TP+FP)、召回率 = TP/(TP+FN) |
| **AP** | PR 曲线下的面积（每个类别独立算） |
| **mAP@0.5** | IoU 阈值 = 0.5 时的 mAP |
| **mAP@0.5:0.95** | IoU 阈值从 0.5 到 0.95 步长 0.05 的 mAP 平均 |
| **mAP@small/medium/large** | 按目标尺寸分组的 mAP |

#### YOLOv8 整体架构（必须能画出结构图）

```
Input (640×640×3)
    ↓
Backbone: Conv → Conv → C2f → Conv → C2f → Conv → C2f → Conv → C2f → SPPF
    ↓                                                                    ↓
   P3 (1/8)   P4 (1/16)                                            P5 (1/32)
    ↓             ↓                                                     ↓
    └─────────────┼──────────────┘
                  ↓
Neck (FPN+PAN): 自顶向下 + 自底向上融合
                  ↓
Head: 解耦头 (分类分支 + 回归分支)
    ↓                ↓
  分类 BCLoss     回归 CIoU + DFL
```

## 5.4 多目标跟踪 ⭐⭐⭐

跟踪是机器人感知系统的**核心能力**之一，面试出现频率仅次于检测。

### 5.4.1 跟踪范式

| 范式 | 代表方法 | 核心思想 | 掌握程度 |
|------|---------|---------|---------|
| **Tracking-by-Detection** | SORT/DeepSORT/ByteTrack | 先检测 → 再做数据关联 | ⭐⭐⭐ **主流范式** |
| **Joint Detection-Tracking** | FairMOT/ CenterTrack | 检测和 ReID 共享 Backbone | ⭐⭐ |
| **Transformer 跟踪** | MOTR/ TrackFormer | 端到端 | ⭐ 了解 |
| **光流跟踪** | RAFT + 关联 | 稠密跟踪 | ⭐ 了解 |

### 5.4.2 SORT 算法详解 ⭐⭐⭐

SORT（Simple Online and Realtime Tracking）是所有现代跟踪器的基石。

```text
SORT 核心流程：
    1. 目标检测（如 YOLO）得到每帧检测框
    2. 卡尔曼滤波预测已有轨迹在当前帧的状态
    3. 匈牙利算法对检测框和预测框做 IoU 匹配
    4. 匹配成功 → 卡尔曼滤波更新轨迹
    5. 匹配失败的检测 → 新建轨迹（先 tentative）
    6. 匹配失败的轨迹 → 保留若干帧（未匹配阈值），仍不匹配则删除
```

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **状态向量** | `[x, y, s, r, dx, dy, ds]`（7 维，s=面积，r=宽高比） | ⭐⭐⭐ |
| **卡尔曼滤波配置** | 匀速模型、低置信度检测的匹配策略 | ⭐⭐⭐ |
| **匈牙利匹配** | `scipy.optimize.linear_sum_assignment`、代价矩阵 = 1 - IoU | ⭐⭐⭐ |
| **ID 管理** | 新目标分配新 ID、删除超过阈值未匹配的轨迹 | ⭐⭐⭐ |
| **级联匹配** | DeepSORT 的改进：优先匹配高置信度、最近更新的轨迹 | ⭐⭐⭐ |

### 5.4.3 ByteTrack ⭐⭐⭐（当前工业主流）

ByteTrack 的核心贡献是 **BYTE 关联策略**。

```text
ByteTrack vs SORT 的关键区别：
    SORT: 只用高分框（score > 0.5）做匹配
    ByteTrack: 高分框做第一次匹配 → 未匹配的轨迹用低分框做第二次匹配
    
    直觉：低分框可能是被遮挡的目标，仍然含有有效的位置信息
```

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **BYTE 策略** | 两阶段匹配（高分→低分） | ⭐⭐⭐ |
| **低分框处理** | 第二次匹配时的 IoU 阈值更宽松 | ⭐⭐⭐ |
| **与检测器的配合** | 需要检测器输出 score（YOLO 天然满足） | ⭐⭐ |

### 5.4.4 DeepSORT

| 知识点 | 详细内容 | 掌握程度 |
|--------|---------|---------|
| **ReID 特征提取** | 额外的小网络提取行人/物体特征、余弦距离 | ⭐⭐⭐ |
| **外观+运动融合** | 级联匹配：马氏距离(运动) + 余弦距离(外观) 加权 | ⭐⭐⭐ |
| **特征更新策略** | 每帧匹配后更新轨迹特征（EMA 方式） | ⭐⭐ |
| **ReID 训练** | Triplet Loss + Cross-Entropy、需要 ReID 数据集 | ⭐⭐ |

### 5.4.5 跟踪评估指标

| 指标 | 含义 | 掌握程度 |
|------|------|---------|
| **MOTA** | `1 - (FN+FP+IDSW)/GT`，综合评估 | ⭐⭐⭐ |
| **MOTP** | 匹配后的平均位置误差 | ⭐⭐ |
| **IDF1** | ID 匹配的 F1-score（评估 ID 一致性） | ⭐⭐ |
| **HOTA** | 综合了检测和关联的更高阶指标 | ⭐⭐ |
| **IDSW** | ID 切换次数（评估跟踪稳定性） | ⭐⭐⭐ |
| **MT/ML** | 跟踪轨迹 ≥80% 为多数跟踪（MT），≤20% 为多数丢失（ML） | ⭐⭐ |

### 跟踪在机器人视觉中的应用

- **障碍物追踪**：实时追踪行人/车辆的位置和速度 → 碰撞预测
- **目标跟随**：机器人锁定并跟随特定目标（如运货机器人跟随人）
- **速度估计**：通过轨迹估计目标速度 → 运动预测
- **轨迹预测**：基于历史轨迹预测未来位置 → 路径规划
